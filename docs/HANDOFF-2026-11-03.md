  **`rr3::reapDetachedThreadWorker`, `pthread_bridge.cpp:5633`**.
* `0x1f6d5d0` is `kAssetSingletonElfVa`, the asset singleton's GOT slot as an

  appear before the dry load) runs a diagnostic every 1 s timeout that reads
  `*(resolveMainImageLoadBias() + 0x1f6d5d0)`. Before the main image is loaded

  unmapped, so it faulted. On Eden the first tick came after loading (or the
  address happened to be readable), so it never crashed there. The console's
  slower boot (32 MiB read from romfs on SD) moved the first tick into the
  window.

So the console crash since at least the 292,710 B run was **a diagnostic
probe in the reaper thread**, not EGL, not the dry load, not memory. Each
earlier log "ended" wherever the boot thread happened to be when the reaper's
first tick fired.
