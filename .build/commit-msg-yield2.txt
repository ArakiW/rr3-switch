THE LOG IS BUFFERED AND THE FRAME LOOP YIELDS, SO THE LOGGING CAN BE OFF

MEASURED 2026-11-10: rounds percall1 and yield2, the same binary, the same
card, the same guest state, the same 400 s.

    round      configuration                                 race screen  lights  frames  log lines/frame
    chunk3     per-line flush, no instrument                        10        7     5280        41.9
    percall1   per-line flush + the new instrument                 10        7     1055       206.7
    yield2     BUFFERED log + an explicit 2 ms yield, percall = 0  36       27     2280        52.9

THE CARD WRITE WAS THE GUEST'S CPU LIFELINE.  The per-call log wrote 42
lines a frame and flushed each one onto the card; a card write WAITS, and the
CPU is free during the wait, so that wait was how the guest's other threads
got any time at all.  REMOVING THE WRITES SPEEDS THE PORT UP AND STARVES THE
GUEST -- which is exactly what the four rounds with percall = 0 showed: the
guest never got past the event map (race screen 0), with the front end itself
drawn perfectly.

THE REPLACEMENT IS AN EXPLICIT YIELD, NOT A CHEAPER WRITE:

  * recovery_guard.cpp: the lines go to stdio's buffer and the file is
    flushed every 64 lines, so the card sees about one write per frame and a
    half instead of forty-two.
  * guest_view_probe.cpp: the frame loop yields 2 ms EVERY frame, however
    long the frame was -- because the frames that need the yield are the long
    ones (during the loading phase the guest's own work is 300-600 ms a
    frame).

AND THE GUEST IS NOW BETTER FED THAN EVER: with percall = 0, the buffered log
and the yield, the round reached race screen 36 and start lights 27 -- the
best of any round, against 10 and 7 for chunk2 and chunk3.  So the logging can
be off and the default is percall = 0 again.

AND THE PER-CALL LOGGING WAS NOT THE WHOLE COST EITHER: the round that added
the new instrument wrote 206.7 lines a frame and its race frame was 144.5 ms
against chunk3's 35.0 ms.  So the next target is named by the same
measurement: 52.9 lines a frame remain, and they are the ASSET-SERVICE lines
(served-digest, open-ok, fs-candidate, guest-scanf-bounded, guest-log-any,
guest-free-seq) -- not per-call lines, and not gated yet.

THE RULE, IN ONE LINE: a diagnostic that is load-bearing must be made CHEAP,
not REMOVED.
