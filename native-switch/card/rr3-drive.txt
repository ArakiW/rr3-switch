# The closed-loop steering for the race-state probe.
#
# The port reads the guest's OWN race state out of guest memory (the
# RuleSetModifier_RaceMetrics object) and steers on the guest's own progress
# metric along the track's spline. See native-switch/source/race_state_probe.cpp.
#
# enable=1   the closed loop drives the steering axis, the throttle and the brake
# probe=1    read the race state but do not steer (diagnostic only)
# base=<f>   the initial steering magnitude, 0..1
# sign=1|-1  the initial steering direction
#
# THE SIGN IS NOW -1, AND IT IS NOT A GUESS: IT IS MEASURED.
#
# The loop flips the sign itself when the guest's progress rate goes NEGATIVE
# (the car is travelling against the spline's direction, i.e. round the track
# the wrong way), so sign is only the starting guess.  The starting guess
# WAS wrong for the circuit this script drives.
#
# MEASURED 2026-10-24, and the port's own archives (20261024-121056-eden-
# race-steer2 and its mirror): on Spa-Francorchamps "the start straight bends
# left and a car that does not steer runs straight off the right-hand edge",
# and the run that launched with lx=+0.6 ended up on the RIGHT runoff.  So
# a POSITIVE axis 0 steers RIGHT.
#
# The autopilot was running with sign=+1, i.e. steering RIGHT on a straight
# that bends LEFT, and the port's own run summary showed the consequence:
# the car's progress rate collapsed from 100.3 to 6.5 units/frame within
# 60 m of the start and never recovered (archive 20261028-220443 was the HD
# run; the driving measurement is the 2026-10-28 night race).
#
# So: sign=-1.  The loop can still flip it if the rate really does go
# negative.
#
# ---------------------------------------------------------------------------
# CHANGED 2026-10-27: probe=1 -> probe=0, so the loop DRIVES.
#
# "probe=1" was the right setting while the question was "can the port read
# the guest's race state at all" -- and the answer was always no, because the
# guest never got INTO a race: the touch path stalled on the daily-reward
# modal (archive 20261027-172023-eden-f1k).
#
# probe=0 makes the loop drive.  It is INERT until the guest is in a race:
# updateDrive() enables itself only when the metrics object was found AND a
# progress value was seen (race_state_probe.cpp:1031), so it cannot move
# anything in the front end, and it cannot change whether the guest reaches
# the race.  That is why it is safe to change in the same run as the touch
# fix: the two variables cannot interact.
enable=1
probe=0
base=0.30
sign=-1
