# THE MANUAL CONTROL SCRIPT: PROVE THE HUMAN'S INPUT REACHES THE CAR.
#
# WHY THIS FILE EXISTS
# --------------------
# Every round so far ran with "autopilot = 1", where the PORT'S OWN CLOSED
# LOOP owns the steering, the throttle and the brake and the human's inputs
# are overwritten before they reach the guest.  So every measurement of "the
# lap counter" so far has been a measurement of the AUTOPILOT's driving --
# which is a different thing from whether the port is PLAYABLE.
#
# This script is the other half of the question.  It holds the accelerator
# (the guest's BTN_A, bit 0) and WEAVES THE STEERING AXIS, so that a round
# can show three separate things at once:
#
#   1. the port's own gamepad-state line: lx (what the script asked for)
#      EQUALS guest_lx (what the guest actually received) -- the input path
#      is intact;
#   2. the guest's car accelerates while BTN_A is held -- the throttle
#      reaches the car;
#   3. the car's path curves when lx changes -- the steering reaches the car.
#
# THE WEAVE
# ---------
# The steering alternates every 150 frames between +0.5 and -0.5.  A slow
# weave rather than a slalom, because the point is that the car's heading
# VISIBLY follows the stick, not that the car drives well.  (Driving well is
# the autopilot's job, and it is a different job.)
#
# The frames are the PORT'S frame counter, the same counter the touch script
# uses.  At the measured frame rates (13..34 fps) 150 frames is 4..11 s.
#
# The format is pinned by native-switch/tests/test_guest_pad_script_format.py:
#
#     [at <frame>] lx=<f> ly=<f> rx=<f> ry=<f> lt=<f> rt=<f> b=<hex>
#
# Every key is optional and a key that is absent keeps the value it had
# before.  `b` is a hex bitmask over the guest's ControllerButtons ordinals
# (bit 0 = BTN_A, bit 2 = BTN_X).
#
# WHY BTN_A IS HELD FROM FRAME 600
# --------------------------------
# MEASURED 2026-11-02 (q109, archive 20261102-054302-eden-rr3-q109-confirm-
# button): holding BTN_A over the window dismisses the guest's in-race
# tutorial dialog -- the synthetic touch does NOT (the layer that owns the
# coach mark is not the layer the port's touch reaches).  The same button is
# also the accelerator, so one hold does both.
