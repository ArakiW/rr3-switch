# THE CONSOLE'S PAD SCRIPT: THERE IS NONE, ON PURPOSE.
#
# WHY THIS FILE HAS NO EVENTS
# --------------------------
# MEASURED 2026-11-04 (q149): with the port's own closed loop out of the way
# (autopilot = 0) the PLAYER's input reaches the car, end to end:
#
#     phase=scripted-state ... mode=0 path=script
#         lx_script=0.500 lx_guest=0.500 buttons=0x0001
#         loop_steered=0 physical_active=0
#
# i.e. the axis the human asked for is the axis the guest got, the accelerator
# is the accelerator, and the closed loop did NOT overwrite either.
#
# And the car answered: the guest's own distance went 99,695 -> 117,526 in
# 240 frames at speed 7,022, and its path TURNED when the axis changed sign.
#
# So the controller belongs to the player.  A script that holds the throttle
# would take the throttle away from them again -- the guest sees "accelerator
# held" no matter what the player's right trigger does, and "brake held"
# while the accelerator is down is just braking.  ⇒ This file ships with NO
# EVENTS: the player's controller drives the car.
#
# The experiment scripts live beside it and are NOT shipped:
#
#   rr3-pad-manual.txt    the weave: the accelerator held, the steering axis
#                         alternated.  It is how the human input path is
#                         measured (tools/Deploy-RR3CardScripts.ps1 installs
#                         it on the emulator card).
#   rr3-pad-autopilot.txt the confirm-then-throttle script, for the rounds
#                         that measure the port's OWN closed loop.
#
# The port reads this file and finds no line at or before the current frame,
# so the physical path is the only one that applies -- which is the point.
#
# The format, for reference:
#
#     [at <frame>] lx=<f> ly=<f> rx=<f> ry=<f> lt=<f> rt=<f> b=<hex>
#
# Every key is optional and a key that is absent keeps the value it had
# before.  `b` is a hex bitmask over the guest's ControllerButtons ordinals
# (bit 0 = BTN_A, bit 2 = BTN_X).
